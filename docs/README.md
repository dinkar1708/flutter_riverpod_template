## Documentation Standards

### File Naming
- Use `SCREAMING_SNAKE_CASE.md` for top-level technical docs
- Use `kebab-case.md` for product/business docs
- Use descriptive names that clearly indicate content

### Content Structure
Each document should include:
1. **Title** - Clear, descriptive heading
2. **Overview** - Brief summary (1-2 paragraphs)
3. **Table of Contents** - For longer documents
4. **Main Content** - Well-organized sections
5. **Code Examples** - With syntax highlighting
6. **References** - Links to related docs/resources

### Code Examples
```dart
// Always include context and comments
@riverpod
class Counter extends _$Counter {
  @override
  int build() => 0;

  void increment() => state++;
}
```

## Project Context

### Tech Stack
- **Framework**: Flutter 3.44.1
- **State Management**: Riverpod 3.0+ (code generation)
- **Architecture**: Clean Architecture with feature-based structure
- **API Client**: Dio + Retrofit
- **Navigation**: AutoRoute
- **Testing**: flutter_test, Maestro, Appium
- **Security**: flutter_secure_storage, envied (obfuscated env vars)

### Key Features
- ✅ Secure authentication with persistent sessions
- ✅ GitHub API integration (users, repositories)
- ✅ Material3 design with dark mode
- ✅ Environment-based configuration
- ✅ Comprehensive unit tests (44+ tests)
- ✅ E2E testing with Maestro & Appium

### Project Stats
- **Lines of Code**: ~5,000+ (excluding generated files)
- **Test Coverage**: 70%+ (business logic)
- **Platforms**: iOS, Android
- **Min SDK**: iOS 12+, Android API 21+

- Adding new features → Update `features/`
- Changing architecture → Update `technical/ARCHITECTURE.md`
- Improving security → Update `technical/SECURITY.md`
- Adding tests → Update `testing/`
